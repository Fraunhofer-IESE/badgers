    Generating missing data¶

    Missingness is the defect where some observed values are simply not recorded (np.nan in the output). Real pipelines rarely get to see complete data: sensors drop out, forms are left blank, values exceed a recording range. The mechanism matters as much as the amount — the same 20% of missing values behaves very differently depending on why the values are missing:

    Mechanism Meaning In badgers (selector) Legacy one-parameter
    MCAR — missing completely at random a value goes missing independently of everything else BernoulliSelector([col], rate=...) MissingCompletelyAtRandom
    MAR — missing at random missingness depends on another, observed variable (e.g. values of X are high) TopQuantileSelector([col], column=..., driver=...) DummyMissingAtRandom
    MNAR — missing not at random a value's own (unobserved) magnitude drives its missingness TopQuantileSelector on itself DummyMissingNotAtRandom

    The notebook shows both ways of expressing these mechanisms:

    1. Acting on the observation process — the legacy one-parameter generators: percentage_missing decides how much goes missing, the generator class decides why. They do not use a DGP and nothing is propagated.
    2. Explicit selectors — the same three mechanisms expressed as selector objects, which decide which cells are selected. Intensity (rate / quantile) lives on the selector, not on generate().

    Goal¶

    Hide cells (write NaN) with different mechanisms: completely at random, related to another column (MAR), or related to the hidden value itself (MNAR) — including the causal-graph variant.

    Part A — Acting on the observation process (legacy one-parameter, no DGP)¶

    These generators take a single percentage_missing value: how much goes missing. Why it goes missing is hard-coded by the class (MCAR / MAR / MNAR). No causal model is involved and no propagation happens.

    Missing completely at random (MCAR)¶

    MissingCompletelyAtRandom replaces values with np.nan independently at random — the fact that a value is missing carries no information.

    Missing at random (MAR)¶

    DummyMissingAtRandom makes missingness depend on another, observed feature: for each column, a reference column is drawn uniformly at random among the other columns, and the missing probability grows as the (normalized, reversed) values of that reference column. Low values of the reference column go missing first. Looking only at observed data one can partly explain the missingness (it correlates with the reference column), but it cannot be fully predicted.

    Missing not at random (MNAR)¶

    DummyMissingNotAtRandom makes a value's own magnitude drive its missingness (unlike the other two generators, percentage_missing has no default value — pass it explicitly): the larger the original value, the more likely it is missing. Here the missingness biases the observed data — e.g. peak values systematically vanish.

    Part B — Explicit selectors on a causal graph¶

    CausalMissingnessGenerator expresses the same three mechanisms with selector objects on a fitted DGP. It writes NaN at the affected cells of the perturbation nodes and does not propagate: missingness is a property of the measurement process, not of the data-generating process (a descendant can still be observed).

    Takeaways¶
      

    • Missingness only hides cells (NaN); values and shape are untouched.
      • 

    • The mechanism decides which cells hide: random (MCAR), conditioned on another column (MAR), or on the value itself (MNAR).
      • 

    • The causal variant is chooser-only: hidden cells do not cascade to descendants.
      •
